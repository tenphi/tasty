Close five more gaps in the precompiled-catalog configuration guard.

- **A rewritten `$$` function definition invalidates its catalog.** With `polyfills.functions` enabled, `configure()` compiles each declarative definition into a closure and leaves `getGlobalFunctions()` empty, so the fingerprint saw only a name and an arity: changing `$$scale` from `2 * $value` to `3 * $value` compared equal and a source-identical chunk was served the old expanded CSS. The definitions the host passed to `configure()` are now recorded and compared by value, in both polyfill modes.
- **Theming no longer disables a catalog.** `configure({ tokens })` was fingerprinted, but those emit `:root` custom properties that the asset excludes, and a chunk written against `#brand` compiles to `var(--brand-color)` whatever the palette says. Recording them rejected every catalog on any theme change, contradicting the documented promise that tokens and palettes stay dynamic. Only `replaceTokens`, whose values are baked into declarations, is fingerprinted.
- **Constructing an SSR collector no longer drops a valid catalog.** Registration is a side-effect import that runs before the host's own `configure()`, and `ServerStyleCollector`'s constructor applied — and therefore validated — registered dependencies. A collector built in that window compared against defaults and permanently rejected a catalog that matches once configuration is installed. The seed now happens inside whichever collector method first consults the catalog, so it lands at the first style-producing operation on every path — including the standalone at-rule hooks (`useKeyframes`, `useCounterStyle`, `useFontFace`), which go straight to the collector and never reach `collectInternals()`.
- **A malformed manifest is ignored rather than thrown from.** The top-level value is now guarded before it is dereferenced, so an imported JSON file that is `null` or not an object is warned about like any other invalid shape.
- **The precompiled benchmark asserts it is measuring precompiled styles.** Restricting hits to the catalog's own document turned every lookup in the iframe-based harness into a miss, leaving the "Precompiled Tasty" case reporting the runtime path. The harness now runs in the document that owns the CSS, and the run fails outright if the case is not served from the catalog — a class name is `hashString(cacheKey)` either way, so nothing else distinguishes a hit from a miss.
